# Maintained media in the existing daily source publisher

The existing `scripts/publisher-source-maintenance.mjs` → `publish-public-source.mjs`
→ `source_refresh.py` command now selects current FAQ/Sunshine/Guru images and the
Materials root catalogue through their existing tested exporters. It reuses the
catalogue's bounded resource GET, exact approved parent release, recorded public
reference permission and metadata-only HEAD observations. No image/video bodies,
patient data, new account credentials or recurring jobs are introduced.

The private candidate feed carries per-pair source ownership and a delivery cache.
Only the existing verified-publication boundary installs that feed. A complete
source can withdraw its own association; another source's association survives.
An anonymous reader gate does not erase a maintained reader's selected image.
Robots restrictions remain separate from parent eligibility. Transient delivery
failures preserve an existing selected use; unknown/unassociated items remain held.

The 16 October local candidate adds 404 knowledge and 663 catalogue references:
66,537 → 67,604 images; 71,099 approved parents and 19,289 videos are retained.
This candidate evidence does not claim deployment, indexing or leads. Production
receipt and the actual native upkeep result remain the release acceptance.

## R2 progress and failure evidence

R2 remains metadata-only: three 200-query segments, with at most one same-job continuation (1,200 requests maximum) solely for checkpointed incomplete coverage. Source errors, source holds and possible mutations never enter that continuation. Progress is now
checksum-verified and persisted separately from the accepted publication, so a
failed run does not destroy its cursor/observations. Every complete proof reports
the oldest/newest page observations and each pass's actual time range; a completion
timestamp alone cannot make old observations fresh. Stale cycles restart. Incomplete
coverage cannot start source publication or count as verified.

The compact failure artifact now includes actual completeness, metadata-page,
pending-change, unstable-object and source-exception counters, plus grouped reasons.
The historical failed run 38802444272 did not retain those counters; they must not
be reconstructed by guessing. Its source phase was verified unchanged, its mutation
journal was empty, and current live module/version checks preserved the last-good
release before owner reconciliation. That history remains a failed run.
