# Ability public reference illustrations: import and render plan

The source package is ready for **1,899 exact image objects on 47 existing `/abs` parents**: 951 question illustrations and 948 example illustrations, grouped into 957 source reference items. The founder's 16 October publishing instruction is recorded in `reference-render-plan/reference-publication-consent.json`, bound to the exact parent-image list and the accepted source metadata hashes. It authorizes this public REFERENCE use and a separate enquiry CTA. It is a project authorization record, not a new copyright licence; ownership, licence and licence URLs remain unknown. Those unknown fields do **not** create another human publishing-approval requirement for this exact scope.

`reference-render-plan/parent-render-index.json` identifies each parent manifest by its exact URL, path and SHA256. Each of the 47 `parents/*.json` files contains source Question/Keyword/E1–E3 context, exact illustration URLs/object keys, source-row/export/object evidence, purpose-based alt/caption suggestions, consent reference and one CTA to **9100181181**. The alt describes the illustration's purpose, not an unverified scene. When Keyword is absent, it names the source reference item. The largest parent receives 80 illustrations. `unmapped-asset-dispositions.jsonl` retains the other **63 objects** separately; none is assigned to a new parent. F2 is never the routing or parent source, including question 627's saved 404.

## Windows integration sequence

1. **Stage metadata and candidate use through the existing catalogue adapter.** The existing `catalogue_v2.import_catalogue(..., candidate_path=...)` reads `page_url` and `image_url` JSONL and retains the complete row as observation evidence, with uses marked `candidate_not_approved_for_sitemap` (`catalogue_v2.py:310–327`). `candidate-media-import.jsonl` has that shape. It is a source candidate stream, not a command to rebuild or write a production database now. Preserve existing asset identities when the same exact URL already exists: `Writer.media` derives URL-based catalogue IDs, which differ from the source object's bucket/key ID. Retain the latter as external provenance instead of replacing an existing primary key.

2. **Map enrichment into the existing normalized schema in the owner's import transaction.** `website_sm2_assets`: source identity/key, source Keyword/Question as contextual name/description, and full semantic context/provenance/consent in `descriptive_metadata_json`. Retain unknown credit/copyright/licence fields. `website_sm2_asset_renditions`: exact URL identity, declared MIME/size, ETag in transform/source metadata; leave dimensions and byte SHA256 unknown rather than treating ETag as a byte hash. `website_sm2_source_imports`/`observations`: bind file, row and consent hashes. `website_sm2_media_uses`: existing parent page ID, exact asset/rendition, role, proposed alt/caption/context and reference key `eipassessment:<question_id>:<role>`. Keep the planned slot separate from an observed DOM placement; `page_content_version_sha256` remains null until actual page evidence exists. The existing `import_public_media` accepts only FAQ/Sunshine/Guru (`catalogue_v2.py:388–423`): an assessment row must not be relabelled as one of those families. A narrow assessment-reference import bridge may reuse `Writer.media`, `Writer.observation` and `Writer.use`, retaining candidate state. No DDL is needed for these fields.

3. **Consume the per-parent manifest in the existing `/abs` public document publisher.** Add one `AbilityReferenceIllustrations(parent_url, manifest)` content component/section to the existing parent composition, preserving the URL and the rest of its content. This is the precise input/output contract, not a claim that a consumer is already implemented: the available local source does not establish a current `/abs` reference-section consumer. Windows owns the existing parent publisher hook. Render one public, server-delivered `<section id="ability-reference-illustrations">`; each reference item shows its source question and labelled E1–E3 reference examples. Render each exact image in a `<figure>` with its proposed `data-*` markers, escaped purpose-based `alt` and `<figcaption>`. Text interpolation must escape source values; do not inject source text as raw HTML. Use an actual `img src` (lazy loading is fine), not a new route or a link-only substitute. No response inputs, forms, scores, child identifiers, session writes or individual results belong to this section. Its notice states that limitation. Render the manifest's single separate Pinnacle/tel CTA once in this new section, rather than once per image; existing site-shell contact links are separate.

4. **Qualify observed use through the existing publisher lifecycle.** Current `managed_media_sources.SOURCES` recognizes only maintained knowledge and catalogue sources (`managed_media_sources.py:10–14`), so this package must not be passed as an already supported managed source. Add a narrowly scoped `ability_reference_illustrations_v1` adapter in the owner's next source change, bound to this consent/pair hash, after the component is integrated. It must match current parent HTML image references and source markers to the exact planned pairs, apply the existing delivery/robots/parent gates and feed only qualified rows to existing reconciliation. Generic `source_refresh.apply_resources` currently holds new media references (`source_refresh.py:141–175`); resolve only this proven authorized source, not unrelated holds. Keep new uses `HOLD_UNTIL_RENDERED_DELIVERY_AND_PARENT_QUALIFIED` until proof exists. Use the actual observed content/source hash for admission, never a proposal-manifest hash as fake rendered proof. Complete future source snapshots may withdraw only their own prior managed uses; missing/partial input is not deletion evidence. No current PR92/publication files are changed by this package.

It does not cover `pbn-test/Ability/Questions/` or `pbn-test/Ability/Examples/`. Add these two exact public prefixes in the next source version, alongside the newly qualified approved-key associations.
