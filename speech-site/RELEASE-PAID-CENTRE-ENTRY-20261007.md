# Paid-centre first-screen enquiry repair — 7 October 2026

## Problem and scope

The legacy origin serves different desktop and mobile centre bodies. Mobile Guntur and Khajaguda begin with a large promotional banner, a long heading and an immediately loaded YouTube iframe, before useful local next steps. One shared, guarded centre-body module adds locality, a short developmental benefit, Call 9100 181 181 and a centre-selected assessment-enquiry link ahead of that content. The same module covers Guntur, Khajaguda, Kakinada, Rajahmundry and Labbipet. Gurunanak Road already uses the accepted Astro centre page and is checked unchanged.

## Implementation

- Exact existing paths only. The actual centre profile-image identity and known single centre-body/introduction/heading structure must match. Existing unknown/private/error bodies pass through. The wrapper retains the original response after a repair-side exception.
- General developmental-support default. Exact allowlisted `utm_content` values can select speech, occupational, ABA or autism copy and the corresponding enquiry preference. Unknown/raw input never enters the markup. Google `gad_source`/`gad_campaignid` and existing recognised click/UTM keys remain eligible; the landing URL remains intact.
- Existing canonical URLs, approved header/footer, centre facts, images, evidence, lower-page narrative, original forms and tags remain. The old introductory heading becomes a short subordinate heading; the new introduction owns the H1. Locality does not repeat Khajaguda's ambiguous historical Mehdipatnam label or Rajahmundry's invalid postcode fragment.
- YouTube becomes an accessible click-to-load control using the original video ID. No video frame loads before selection. Mobile entry actions leave room for the existing floating legacy controls; browser acceptance checks actual click targets, not only element dimensions.
- The assessment action uses the existing receiving form with valid centre/service selection. No duplicate intake screen, fake name, reduced backend validation or synthetic lead is introduced. Existing consent-gated contact measurement is extended; navigation does not become an accepted enquiry or connected call. Current centre Ads tags are retained; this release does not claim a new Ads forwarding-number integration or end-to-end CRM attribution.
- No new domain, spending, campaign, scheduler, common-shell redesign, static asset rebuild or route/binding change. The native centre Worker keeps all ten captured modules and replaces only its entry/measurement modules, adding the shared entry module.
