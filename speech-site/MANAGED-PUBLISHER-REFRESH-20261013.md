## Publisher input contract

The existing catalogue/source coordinator supplies a complete reviewed release archive generated by `catalogue_v2.py build-normalized` and its actual reviewed source/eligibility receipts. Candidate DOM/R2 associations alone cannot select it. Preserve source holds, valid timestamps, exact current publisher versions, image uses and video metadata. Do not promote generated video dates/durations/player IDs or invent approval from storage existence.

`tooling/sitemap-manager/publication-selection.json` is now the build's selected immutable publisher artifact. It declares archive bytes SHA256, generated release identity, full reviewed eligible-page count and provenance. Replace this pointer only with the source-reconciled new archive. Invalid bytes, unsupported members or unexpected counts fail before the existing valid build is replaced. The default pointer still selects the previously accepted71,047-page baseline; this commit does not imply that the new media profiles are published.

`npm run build` retains the existing prebuild/Astro/postbuild path. `build-managed-sitemaps.mjs` consumes the selected artifact, composes the approved shared shell and Anek presentation, derives counts from its manifest and atomically installs the valid composed output. It no longer contains a hard-coded source release ID,161-HTML assertion or225-file assertion. No script uses crawl/object/extraction times as page lastmod.

## Repeatable release

Use existing Node/Python and secured Cloudflare/GitHub login. The baseline receipt must identify the current verified live Worker and complete asset union. `release-managed-refresh.mjs` retains ignored checkpoints and refuses stale source/version/route inputs.

```text
node scripts/release-managed-refresh.mjs capture --id <unique-release-id>
npm run build
node scripts/release-managed-refresh.mjs prepare --id <unique-release-id>
# Review the generated manifest, media profiles, native/browser proof and diff.
# Commit the actual selected artifact/pointer/code and push the existing branch.

```

Later cycles pass `--baseline-receipt`, `--baseline-manifest` and `--previous-release` for the latest verified full-union publication. Current default paths are explicit dated receipt provenance, not a licence to reuse stale live state.

Preparation verifies every unrelated baseline asset and replaces/removes only the exact previous `_managed_sitemaps/` namespace. It retains the complete existing primary module union and entrypoint, replacing only managed runtime/config modules. New XML leaves receive exact routes; existing routes, protected Workers, bindings, consent/intake and the public-document recovery remain preserved. No second managed wrapper is stacked.

Explicitly retired generated navigation/XML leaves receive410/noindex, so an obsolete artifact does not masquerade as a server outage. Protected receiving/authentication/commerce routes cannot be retired through that list. Original source pages/answers are not deleted by this integration.

Rollback restores the exact previous full-asset Worker version and removes only routes added by this release. Verify version/routes and prior public manifest bytes after rollback. A local changed/deleted-source fixture is not a genuine production refresh proof: record the real source delta and live artifact/retirement readback separately.
