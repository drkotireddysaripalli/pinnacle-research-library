# Legacy origin retirement — inventory review

9 October 2026. Family-level inventory reconciled against existing source manifests, routing code and release receipts. No duplicate estate crawl was started. The separate route repair below was completed by the website owner in this same pass.

## Decision

**The legacy public origin cannot yet be retired.** The maintained runtime serves many complete families, but the homepage, residual therapy/corporate pages, current staff profiles, Guru and most older knowledge details still fetch legacy HTML. Unknown public Mirracles identities also fall through. The route-only repair now leaves 307 routes; the existing 3,706-asset union is unchanged. These are deployment configuration counts, not a count of migrated pages.

Keep the existing authoritative inventories below. This document is a family-level retirement checklist, not another URL register. No defensible current total of all remaining legacy pages exists in the reviewed records.

## Incident fixed in this pass

The two new exact-host catch-alls shadowed existing API routes. All original 23 API route registrations existed, but Mirracle staff/FAQ calls received HTML and www website-data calls reached the wrong origin. Source `29c13f9` restored 42 explicit API/socket routes, preserving all 265 original routes. Three authenticated read-only API checks returned valid JSON, and all six affected page/device requests returned HTTP 200; five had failed previously. See [incident and public proof](CLOUDFLARE-ORIGIN-INCIDENT-20261009.md) and [configuration receipt](deployment/api-route-restoration-20261009.json).

This fixes the reproduced outage. It does not migrate the restored legacy pages. Keep the pinnacleblooms.org domain and its useful URLs permanently; the eventual retirement target is the legacy ASP.NET/IIS application/origin, not the domain, Cloudflare routing layer or every existing API Worker.

## Retirement sequence and acceptance

1. **Routing outage fixed; remove remaining public origin dependence next:** reconcile unresolved Mirracles identities and move the homepage to maintained source. Use the existing private alert and saved source records; preserve consent/publication eligibility. Then address the residual therapy/service and high-demand knowledge templates.
2. **Complete original-source dispositions by family:** current staff, careers/jobs, Guru, news/resources/media/events, legacy knowledge details and the Materials/Interventions export. Each canonical identity needs preserved native content, a justified equivalent merge/redirect, accurate retirement/404, or a named unresolved dependency. One template/importer can cover a family; the existing shared transforms alone cannot.
3. **Remove residual discovery/asset dependencies:** current root sitemap code still proxies staff/bots to `psapi` and Mirracles to `/mirraclesitemap`; direct `/mirraclesitemap` also fetches origin. The exact `/sitemaps/centres.xml` route is already served by Portal's maintained asset and overrides the root wildcard. Homepage and robots obtain origin responses, and the Portal catch-all calls `fetchPublicOrigin`. Replace/retire residual discovery endpoints from authoritative manifests and inventory original images, PDFs, scripts, form/API handlers and method-specific paths. [S2,S13]
4. **Prove independence before shutdown:** exact source/target disposition totals reconcile to each authoritative population; every maintained template serves correct original body/identity with legacy HTML unavailable; required images/media/downloads and real contact/application/enquiry paths work; unknown/retired paths have correct statuses; all sitemap canonicals come from maintained sources; protected operational services have separately verified owners/dependencies. Capture a rollback and bounded post-release origin-request evidence. A Worker route match, rewritten header, HTTP 200 or crawler score cannot satisfy this condition.
